# 07. 검증 보고서

재구현(「영웅의 전장」)이 모든 요소를 갖추고 동작하는지 확인한 결과다. 검증은 세 겹으로 했다. 순수 규칙의 단위 테스트, 20개 전투 전체의 헤드리스 시뮬레이션, 그리고 **ego lite 브라우저**에서 실제 화면을 조작하는 E2E 확인이다.

```
단위 테스트(node --test) → 헤드리스 전투 20개(scripts/sim-run.mjs) → ego lite 실제 화면 조작·캡처 → 결함 수정 → 재검증
```

## 3. 헤드리스 전투 20개

`npm run sim` — 전술 전투는 지휘관을 후방에 두고 군대 AI끼리, 영웅 전투는 단순 봇 지휘관(목표로 이동·공격·기술·무쌍·저체력 후퇴)으로 끝까지 돌렸다. 목적은 **안정성(NaN·멈춤 없음)·성능·균형의 대략적 확인**이며, 실제 플레이어가 지휘하면 결과가 달라진다. 모든 전투가 NaN 없이 끝났고 스텝당 0.06~0.17 ms다.

## 5. 검증 중 발견하고 고친 결함

| # | 증상 | 원인 | 수정 |
|---|---|---|---|
| 1 | 전투에서 클릭·휠이 먹지 않음 | `#app > *` 의 ID 선택자 우선순위가 `.hud { pointer-events:none }` 를 덮어 HUD 전체가 입력을 가로챔 | `#app > .hud` 로 명시 |

## 6. 알려진 한계와 검증 범위 밖

- **자동화 도구의 키 가로채기**: ego lite 자동화에서 `keyboard.press('r')` 는 페이지를 새로 고치고, `'t'` 는 페이지에 전달되지 않았다. 게임 결함이 아니라 브라우저 자동화의 단축키 처리다. R·T 는 합성 `KeyboardEvent` 로 검증했고, 실제 사용자 입력에는 영향이 없다.
- **자동화 중 프레임 정지**: 자동화 명령 사이에 rAF 가 멈추는 구간이 있어 일부 시간 측정은 실제보다 느리게 보인다. FPS 수치는 자동화 오버헤드가 포함된 값이다.
- 소리는 Web Audio 노드 생성까지만 확인했고 귀로 듣는 검증은 하지 못했다.
- 터치 모드는 데스크톱 화면에서 배치와 동작 연결만 확인했고 실제 모바일 기기에서는 시험하지 않았다.
- 균형은 헤드리스 봇 기준의 대략값이다. 실제 플레이 감각에 맞춘 미세 조정은 남아 있다(06 §9).
- 빌드 번들 770 kB(gzip 219 kB)로 Vite 경고가 뜬다(동작 영향 없음).
